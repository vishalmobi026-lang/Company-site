1. The Backend Architecture (FastAPI)

The backend is built with FastAPI. Its job is to handle security, validate data, and talk to the PostgreSQL database.

A. Database Models (models.py)

This file defines how your data "looks" inside the database. We use SQLAlchemy classes to represent tables.

class Enrollment(Base):
    __tablename__ = "enrollments"
    id = Column(Integer, primary_key=True) # Unique ID for each student
    name = Column(String, nullable=False)  # Student name (Cannot be empty)
    course = Column(String, nullable=False) # The course they picked

Learning Point: Every time you want a new feature (like "Blogs" or "Staff"), you must add a new class here first.

B. Data Validation (schemas.py)

This is where we use Pydantic. It acts as a shield. If a user sends "abc" instead of a number for a price, Pydantic catches it and sends an error (Error 422).

class PricingCreate(BaseModel):
    course_name: str
    standard_price: Union[str, int] # We allow both to prevent crashes!

C. The API Routes (main.py)

This is the controller. It receives requests from the internet and decides what to do.

  • @app.post("/enrollments"): Public route for students to apply.
  • @app.get("/admin/enrollments"): Private route (Requires a Token) for you to see students.

2. The Frontend Architecture (React)

React is the "Face" of your app. It uses Components to build the UI and State to remember data.

A. Talking to the Backend (Axios)

We use a library called Axios to send data. Think of it like a mailman delivering your form data to the Python server.

3. Security (JWT Authentication)

How does the app know you are the Admin? We use JSON Web Tokens (JWT).

  1. You login with username/password.
  2. The server sends back a long string (The Token).
  3. React saves this token in localStorage.
  4. Every time you visit a "Private" page, React sends that token in the Header.

Crucial Fix: If you get an Error 401, it means your token is old. Logging out and back in creates a fresh, valid token.
